# 202 — Objectives (Operational Period 1)

**Incident:** workflow-budget-enforcement
**Period:** 1

## Goal

A `dcs/workflows/*.md` file exceeding its allowed line-count ceiling is caught mechanically at merge time, every time — not only when someone remembers to run `wc -l` by hand or an IC improvises a ruling mid-incident. The four files already over CLAUDE.md's ~250-line policy (`plan.md`, `execute.md`, `deploy.md`, `close.md`) get a deliberate, documented, finite grandfather ceiling instead of either silently passing forever or immediately reddening the merge-time guard on day one; the six currently-compliant files hold the policy ceiling itself, so none of them can quietly grow past it the way `deploy.md` grew past its own prior ad hoc ruling.

## Acceptance criteria (the Definition of Done)

1. `tests/test_doctrine_integrity.py` gains a new check that enumerates `dcs/workflows/*.md` (reusing the existing `workflows()` helper at lines 175-176) and compares each file's line count against a named, per-file ceiling constant, failing the suite (non-zero exit) if any file exceeds its own ceiling.
2. Every ceiling is set so that running `python tests/test_doctrine_integrity.py` against the tree as this incident leaves it is green (exit 0) — the command and its verbatim output are recorded as evidence, not paraphrased.
3. The six files currently within the ~250-line policy (`esg.md`, `init.md`, `loop.md`, `new.md`, `run.md`, `status.md`) get the plain ~250-line ceiling — no silent grandfathering. The four files currently over (`plan.md`, `execute.md`, `deploy.md`, `close.md`) get an explicit grandfather ceiling set at or just above each file's own line count as of this incident's integration commit, with an inline comment naming it as documented technical debt, not a silently-accepted new normal (principle 15: the derivation, not just the number).
4. The line-count measurement normalises line-ending representation before counting, matching the existing `HOT_PATH_BUDGET_KB` check's own idiom (`test_doctrine_integrity.py:263-272`) — defending against the lone-CR / missing-trailing-newline hazard the stem's situation analysts identified, even though the current `.gitattributes` policy makes it non-load-bearing today.
5. `CLAUDE.md`'s "File size" rule is corrected so its "see the guard" clause unambiguously names the new check (fixing the ambiguity situation analyst 1 flagged at CLAUDE.md:133), and states plainly that 4 files currently run under a documented, temporary grandfather ceiling rather than full ~250-line compliance.

No previously-passing check in `tests/test_doctrine_integrity.py` regresses: a full suite run before this incident's changes and after shows the same baseline pass count plus exactly the one new check, zero unrelated failures. That is separate, larger content-editing work per file — each plausibly its own future incident, matching the `doctrine-hot-path-trim` / `schemas-md-trim` precedent of trimming as its own dedicated incident rather than bundled with guard-building (`hot-path-budget-eol-sensitivity` shipped the guard mechanism separately from the trim that preceded it). Criterion 3's grandfather ceiling exists specifically so this incident does not need to attempt that surgery under Type-1 time pressure.

- **Resolving `strategy-compaction-loses-history`** (the STRATEGY.md decline-history fragility a situation analyst flagged out-of-territory during this incident's stem) — already split into its own QUEUED register row, independent root cause.
