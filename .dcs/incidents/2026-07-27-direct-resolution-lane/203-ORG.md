## Execution mode

**Sequential: S1, then S2.** IC ruling at command point 2, overriding the
chief's offered parallel default. The territories *are* disjoint — verified by
`fnmatch`, not by trusting `partition_ok` — so parallelism was available. It was
declined for two reasons the chief itself named as risks:

1. **The verification surface is shared.** Both taskings run
   `tests/test_doctrine_integrity.py` against the same worktree. Run in
   parallel, S2 can observe check 15 while S1's edit is half-written — a
   spurious red, or worse a spurious green if S2 finishes first.
2. **The state literal is a cross-tasking contract.** `RESOLVED` must be spelled
   identically in both territories and nothing mechanical enforces that. Running
   S2 second lets it *read S1's landed literal* instead of trusting the plan's
   copy of it.

The IC's words: on a Type 1 adjacent to a guard we may not touch, latency loses
to margin. The cost is one round.

## Why 203 exists this period

Type 1 always writes it (`forms.md`), and activation departs from the Type 3
default twice over: a Logistics Chief is activated, and execution is sequential
rather than plain parallel.
