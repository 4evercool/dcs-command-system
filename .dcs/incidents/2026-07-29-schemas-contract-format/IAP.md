## Objectives (summary of 202)

Цель: контракты возврата агентов объявлены машиночитаемо и сверяются
механикой — у каждого раздела-контракта `dcs/references/schemas.md`
разборное объявление полей, у каждого устава `agents/dcs-*.md` блок
контракта того же формата (у командира впервые), слияние-сторож
`tests/test_doctrine_integrity.py` сверяет их между собой и разбирает
JSON-примеры, расхождение `advisories` устранено.

Критерии приёмки (полный текст — `202-OBJECTIVES.md`):

1. Формат схемы: каждый раздел-контракт `schemas.md` несёт машиночитаемое
   объявление полей; §3 получает полный контракт; §6 привязывает каждое
   поле к его командной точке, слэш-ячеек не остаётся. Население —
   обходом во время прогона.
2. Уставы: каждый `agents/dcs-*.md` несёт блок контракта того же формата;
   у командира впервые (четыре командные точки + `esg_activation`); в
   `<output_contract>` Safety Officer появляется `advisories`.
3. Сторож полей: новая проверка — пары обходом, разбор на лету, ни одного
   литерала имён/счётов; вырождение красное; отрицательное доказательство
   подделкой в памяти; факт и команда — в `214-LOG.md` [IC].
4. JSON-примеры: каждый огороженный блок `schemas.md` разбирается
   стандартным парсером; население во время прогона; ноль блоков —
   красное.
5. Не регресс: три прогона зелёные, проверки 13/14 и бюджет hot path
   держатся.

## Tactics (from the Planning Chief)

1. Один формат объявления на обеих сторонах, разбираемый без эвристик:
   номер раздела-контракта, ровно один агент-производитель, список имён
   полей верхнего уровня; вложенные ключи остаются прозой (измеренные 4
   ложных имени обратного направления пришли из них).
2. Привязку производителя не выводить из фразы `Returned by` — строка §2
   называет двух агентов; объявление называет ровно одного производителя
   на раздел, логист входит через собственную строку `Returned by` §3.
3. §6 — четыре набора, не один плоский: формат несёт измерение
   «командная точка»; `esg_activation` — необязательное поле, едущее с
   любой точкой.
4. Каждый добавленный байт `schemas.md` оплачивается точечным тримом там
   же или переносом провенанса в `doctrine-appendix.md`; мерить до и
   после одной командой.
5. Дисциплина сторожа — копия проверок 13/14: население обходом, разбор
   во время прогона, без литералов, страховка от вырождения на трёх
   уровнях, именованный случай на пару, подделка в памяти по образцу
   13(f).
6. Сторожится одно направление — «поле схемы отсутствует в уставе»
   (измерено: 0 ложных срабатываний); имя проверки не обещает
   двусторонней сверки.
7. Разбор JSON-примеров — отдельная проверка в том же прогоне; ноль
   блоков — красное.
8. Порядок вместо параллельности: прозу пишет одна рука (S1), сторож (S2)
   — после и против фактического дерева (урок §15).

## Deploy / environment plan (Type 1, from the Logistics Chief)

- **deploy_path:** полный деплой одной командой `powershell
  -ExecutionPolicy Bypass -File C:\DCS\install.ps1` (только из `C:\DCS`,
  только после `/dcs-close` — HARD RULE), затем свидетель `python
  tests/payload_check.py` с разборкой кодов выхода по `deploy.md` шаг 7
  (0 и 3 — прошло, 1 и 2 — стоп). Урезанного деплоя не существует;
  `tests/` установщик не копирует — новый сторож доходит до потребителей
  пакета только через `npm publish` (Owner-only).
- **env_deps:** новых переменных, зависимостей, конфигурации нет; сторож
  stdlib-only; `npm test` не меняется. Версия 0.6.13 в `dcs/VERSION` и
  `package.json`; бамп (если будет) — одним коммитом, иначе merge-guard
  красный.
- **migration_ordering:** схемной миграции нет; обязательный порядок —
  внутри инцидента: (1) проза контрактов, (2) сторож, (3) пересчёт
  бюджета на итоговом дереве. Обе стороны обязаны лежать в ветке
  одновременно к моменту `/dcs-close` шаг 1a.
- **rollback_plan:** изменение только добавляющее, состояния нет; откат =
  `git revert` слитого коммита + повторный `C:\DCS\install.ps1`
  (идемпотентен). Новых файлов полезной нагрузки нет — installed-only
  мусора не ожидается. После `npm publish` откат — новой патч-версией,
  действие Владельца.
- **Риски логистики:** запуск `install.ps1` из worktree установил бы
  неслитую ветку (`$repo = $PSScriptRoot`) — деплоить только из `C:\DCS`;
  `payload_check.py` из worktree сравнил бы ветку — запускать из `C:\DCS`
  или с `--repo`; уставы читаются живыми сессиями из `~/.claude/agents/`
  — перед деплоем убедиться, что активных инцидентов нет нигде.

## Risks

1. **Порядок обязателен, хотя территории не пересекаются** — таблица выше
   объявляет sequential; запуск в параллель — единственный риск, теряющий
   период целиком.
2. **Коридор hot path — 153 Б** (37 735 из 37 888 на HEAD, команда — в
   204/S1) при обязательном росте §3/§6. Точечный трим обязателен; трим
   не сходится → deviation к IC, подъём `HOT_PATH_BUDGET_KB` запрещён
   (пересчёт ратчета — осознанное решение IC/Owner, с результата
   слияния, не с ветки — `tests/test_doctrine_integrity.py:121-153`).
3. **Проверка 13 держит `agents/dcs-commander.md` именованной страховкой**
   — его перенесённую через границу строки цитату `schemas.md #6` не
   удалять и не переносить; устав командира правится сильнее всех.
4. **Проверка 14 разбирает `agents/dcs-safety-officer.md` по содержанию**
   — правка `<output_contract>` соседствует с её населением; абзацную
   структуру шага advisory/refutation не трогать.
5. **Критерий 4 сегодня фактически зелёный** (все блоки разбираются) —
   без страховки «ноль блоков — красное» проверка бесполезна и выглядит
   рабочей.
6. **Соблазн S2 подогнать компаратор под расхождение** — запрещён явным
   пунктом постановки задачи; Safety Officer проверяет чтением диффа
   теста, не прогоном.
7. **`esg_activation` — поле, едущее с любой точкой**: в привязке
   командных точек оно обязано быть помечено необязательным, иначе сторож
   даст ложное срабатывание.
8. Обе постановки упираются в `214-LOG.md` (критерий 3) — разрыв
   закрывает IC транскрибированием из возврата S2.
