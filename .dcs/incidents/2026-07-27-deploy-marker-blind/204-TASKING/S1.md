**Contract (do not vary):**

- **Stdlib-only Python.** LF line endings, **no BOM** — `tests/` is inside
  the integrity suite's `SHIPPED_DIRS`, so checks 8/9/10 will read this
  file for BOM, CRLF and non-ASCII. `CLAUDE.md`'s rule against PowerShell
  `Set-Content`/`Out-File` exists because a BOM has broken a hash
  comparison in this repo twice — which is pointedly the same defect class
  as this incident.
- **Invocation:** `python tests/payload_check.py [--repo PATH] [--installed PATH]`,
  defaulting to the repo root and `~/.claude`. **The overrides are a hard
  requirement, not a convenience:** without `--installed`, criterion 2 is
  unsatisfiable without either installing or mutating `~/.claude` in place,
  and both are forbidden.
- **Payload set DERIVED by walking**, never a hardcoded file list. A
  literal list is exactly the derived fact principle 15 forbids, and it
  would go silently green on a payload file added after it was written.
  Walk the three roots the installers walk:
  - `dcs/` recursively → `~/.claude/dcs/` (`install.ps1:7`, `install.sh:10-11`)
  - `agents/dcs-*.md` → `~/.claude/agents/` (`install.ps1:10`, `install.sh:13`)
  - each `skills/dcs-*/` recursively → `~/.claude/skills/<name>/` (`install.ps1:12-15`, `install.sh:15-19`)

  **Cite those installer line numbers in a comment** so a future reader can
  check the two derivations still agree.
- **Scope `installed-only` to the DCS globs.** `~/.claude/agents/` and
  `~/.claude/skills/` are **shared directories**, not DCS-owned — measured
  2026-07-27: 6 `dcs-*` agents among ~30+ foreign `gsd-*` files, and 10
  `dcs-*` skills among `find-skills`, `humanizer`, `reconciliation`. A
  witness that treats everything under those directories as installed-only
  goes permanently, unfixably red. Only `~/.claude/dcs/` may be treated as
  wholly DCS-owned.
- **Exclude `__pycache__` and `*.pyc` unconditionally on both sides.** The
  two installers disagree here and there is no single "the way the
  installer does it": `install.ps1` passes `/XD __pycache__` for `dcs/` but
  **not** for the skills copies; `install.sh` excludes it via rsync for
  `dcs/` only, and its `cp -R` fallback excludes nothing at all. This is
  not hypothetical — `test_doctrine_integrity.py` imports `dcs_gate.py`,
  which creates `dcs/hooks/__pycache__`. **Reuse the exclusion set
  `tests/test_doctrine_integrity.py` already defines** (`EXCLUDED_DIRS` /
  `BYTECODE_SUFFIXES`) rather than inventing a third rule — read it, and
  say in a comment that you are matching it.
- **Report** four classes — identical / differing / repo-only /
  installed-only — with counts, and for the three non-identical classes the
  file paths.
- **Exit codes:** `0` all identical · `1` anything differing or repo-only
  (a real mismatch) · `3` installed-only files but nothing differing or
  repo-only (merged content complete, installer left stale extras it never
  purges — `robocopy /E` has no `/PURGE`, `rsync -a` has no `--delete`) ·
  `2` environment error, e.g. the installed root does not exist. **Exit 2
  is what lets `deploy.md` keep its "marker unreadable" branch honest
  instead of conflating "cannot check" with "differs".**

**Do NOT** run any installer. **Do NOT** write anything under `~/.claude`.
**Do NOT** add this script to `package.json`'s test script — it compares
